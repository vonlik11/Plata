# Промпт-радар — Итоговый отчёт

## 1. Постановка задачи

Разработать систему аналитики, которая автоматически структурирует логи запросов пользователей к ИИ-агентам. Бизнес-цели:
- Понять реальную эффективность внедрения ИИ
- Найти зоны для автоматизации
- Выявить проблемы пользователей

## 2. Архитектура решения

### Стек технологий
| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| Интерфейс | Streamlit | Быстрая разработка, интерактивность |
| Визуализация | Plotly | Интерактивные графики |
| Классификация | LLM API / TF-IDF + ключевые слова | Семантика + fallback на CPU |
| Кластеризация | KMeans (scikit-learn) | Масштабируемый, предсказуемый |
| Парсинг | Pandas | CSV, JSON, TSV |

### Двойной режим работы
1. **LLM-режим** — семантическая классификация и саммаризация через OpenAI-совместимый API
2. **Fallback-режим** — TF-IDF + ключевые слова (работает без API, на CPU)

## 3. Пользовательский флоу

```
[Upload CSV/JSON] → [Настройка LLM (опционально)] → [Анализ] → [Дашборд] → [Рекомендации CTO]
       ↓                    ↓                            ↓           ↓              ↓
   Парсинг            API подключение          Классификация   Графики      Инсайты
   Нормализация       Выбор модели             Кластеризация   Таблицы      Действия
```

### Шаг 1: Загрузка файла
- Пользователь открывает дашборд и видит область для загрузки (drag & drop)
- Поддержка CSV, JSON, TSV
- Автоматическое определение колонки с текстом
- Предпросмотр загруженных данных

### Шаг 2: Настройка LLM (опционально)
- Включение LLM-режима через toggle в боковой панели
- Указание Base URL (OpenAI, vLLM, Ollama, LM Studio)
- Ввод API Key и выбор модели
- Проверка подключения одной кнопкой

### Шаг 3: Парсинг и подготовка
- Нормализация колонок (request_text, timestamp, user_id и др.)
- Обработка пропусков и некорректных данных
- Оценка токенов если не указаны

### Шаг 4: Аналитика
- **Классификация** — батчами по 20 запросов через LLM, fallback на ключевые слова
- **Кластеризация** — TF-IDF + KMeans (15 кластеров по умолчанию)
- **Саммаризация** — LLM генерирует для каждого кластера:
  - Название сценария
  - Описание болей пользователей
  - Потенциал автоматизации (high/medium/low)
  - Типовые формулировки
  - Рекомендации для CTO

### Шаг 5: Визуализация
- KPI-карточки (запросы, пользователи, токены, удовлетворённость)
- Круговая диаграмма категорий
- Карточки сценариев с саммари и метриками
- Временные тренды + тепловая карта активности
- Топ пользователей + распределение оценок
- Автоматические рекомендации для CTO

## 5. Рекомендации для CTO

1. **Приоритет автоматизации:** «Генерация текста» и «Написание кода» занимают ~40% всех запросов — стоит инвестировать в шаблоны и инструменты.

2. **Проблемные зоны:** Сценарии с удовлетворённостью < 3/5 требуют доработки промптов.

3. **Производительность:** Среднее время ответа 23.2с при 100k токенов — в пределах нормы, но сценарии >30с требуют оптимизации.

4. **Высокий потенциал автоматизации:** Сценарии с типовыми формулировками и низкой вариативностью — кандидаты на шаблонизацию.

## 6. Как использовать с реальными данными

1. Подготовьте CSV/JSON с колонкой текста запросов
2. Откройте дашборд: `streamlit run prompt_radar/dashboard.py`
3. Загрузите файл через кнопку Upload
4. (Опционально) Подключите LLM API в боковой панели
5. Анализ запустится автоматически

## 7. Ограничения и направления развития

### Текущие
- Кластеризация на TF-IDF (без семантики) — при LLM-режиме классификация точнее
- KMeans требует заранее задать число кластеров
- Нет мультиязычности из коробки

### Возможные улучшения
- Замена TF-IDF на sentence-transformers (легковесные, работают на CPU)
- HDBSCAN вместо KMeans (автоопределение числа кластеров)
- Интеграция с реальными API (Jira, Confluence, Slack)
- Алёртинг при аномалиях
- Экспорт отчёта в PDF/Excel
